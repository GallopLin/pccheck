## 3. 注意事项与遗留

- C++ 库的 `PR_ADDR` / `free_space` 是**进程级 static**：同一进程创建多个 writer，会让空闲 slot 队列出现重复编号，可能把已发布的 slot 再分配出去。生产中每个进程只有一个 writer，所以不受影响；但测试或 bench 不能在同一进程里反复新建 writer（T5 最初就是因此误报）。
- `libtest_ssd.so` 本地已重新编译（`-march=native`）。**远端必须在远端重新 `make libtest_ssd.so`**；旧库缺少 `abort_checkpoint`，Python 端只会告警，slot 不能回收。
- 拷贝任务若在借到 chunk 之后、提交 SSD 之前抛异常，该 chunk 不会归还（计数也会偏）。这条失败路径之前同样存在，目前未处理。
- `bench_quant_resume.py` 内有一份独立的旧量化器拷贝（没有下溢防护）。后续做量化实验 E1/E2 时应改为调用 `quantize_int8_blocks`。
- PP 路径仍是"step 后整体保存"，**没有接入** `MultiStreamOptimizer`。本次只是让它支持 DeepSpeed FusedAdam 的分段调用（T1 已验证逐位一致），为方案 A 打基础。
- 远端 PP 环境是 torch 2.1.2 / py3.9，尚未验证。所用 API（`_per_optimizer_states`、`OptState.name`、优化器原生 `step`）在 2.1 中都存在。
